# API

A lib é TypeScript e roda no Node (sobre o `node-hid`) e no navegador (sobre o WebHID). Ela tem duas camadas. O **núcleo** fala o protocolo que toda a família de controles GameSir compartilha: conexão, fila de comandos, heartbeat, leitura e escrita de perfis. Os **modelos** sabem o que cada byte significa num controle específico e oferecem métodos tipados, como "mude a cor do Home" em vez de "grave estes bytes neste offset". Hoje existe um modelo: `Cyclone2`.

| Camada | Conteúdo |
|---|---|
| Núcleo | `GameSirController`: transporte, fila de comandos, heartbeat, eventos, leitura e escrita de perfis, firmware, troca de perfil, vibração. Vale para todo controle que usa o protocolo `0x0F` ([protocolo.md](protocolo.md)) |
| Modelos | descritor (PIDs, tamanhos dos perfis, leitura do report de estado), codecs dos perfis e métodos tipados. Disponível: `Cyclone2` |

Com um Cyclone 2 plugado e o Chrome ou o Edge do computador, os botões desta página rodam os exemplos no seu controle. As luzes e o perfil de jogo voltam ao que eram quando você desconecta ou sai da página.

## Instalação

```bash
npm install gamesir-hid node-hid   # node-hid só no Node
```

- Node 18 ou superior.
- Linux: dar acesso ao `hidraw`, por exemplo com a regra udev `KERNEL=="hidraw*", ATTRS{idVendor}=="3537", MODE="0666"`.

## Conexão

Conectar tem sempre três passos: achar o controle, abrir um transporte (o canal HID) e chamar `start()`. No Node, `findControllers` lista os controles conhecidos e `NodeHidTransport` abre um deles:

```ts
import { Cyclone2 } from "gamesir-hid";
import { findControllers, NodeHidTransport } from "gamesir-hid/node";

const [device] = await findControllers();
const pad = new Cyclone2(await NodeHidTransport.open(device.path));
await pad.start();
```

No navegador, o WebHID só deixa uma página abrir um dispositivo depois que a pessoa escolhe o controle numa janela do próprio navegador. Por isso `requestController` precisa ser chamado num clique. É assim que o botão "conectar controle" desta página funciona:

```ts
import { Cyclone2 } from "gamesir-hid";
import { requestController } from "gamesir-hid/webhid";

const opened = await requestController();   // num clique; o navegador pede permissão
if (!opened) throw new Error("nenhum controle escolhido");
const pad = new Cyclone2(opened.transport);
await pad.start();
```

| Função | Retorno |
|---|---|
| `findControllers(models = MODELS)` | coleções `0xFFF0` dos modelos conhecidos: `{ path, productId, product, model, … }[]` |
| `NodeHidTransport.open(path)` | transporte `node-hid` |
| `gamesir-hid/webhid` | `requestController`, `getAuthorizedControllers`, `WebHidTransport`: o mesmo, via WebHID |

## `GameSirController`

É a base de todos os modelos e cuida do que é igual em qualquer controle da família. `State` é o tipo do report de estado do modelo.

### Sessão

`start()` liga o heartbeat. Sem ele, o controle não manda estado, então chame `start()` logo depois de abrir. A partir daí, `onState` recebe cada report, até 1000 por segundo no cabo. Quem só quer um valor de vez em quando lê `lastState`.

| Membro | Descrição |
|---|---|
| `start({ heartbeatMs = 1000, testMode = false })` | envia o heartbeat periodicamente; sem ele, o controle não envia estado |
| `stopHeartbeat()` · `close()` | para o heartbeat · fecha o transporte |
| `onState(fn)` · `nextState(timeoutMs)` · `lastState` | report de estado a cada envio · próximo report · último recebido |
| `onProfileChanged(fn)` | perfil alterado pelo próprio controle: `{ profileNum, offset, length }` |
| `onDisconnect(fn)` · `isConnected` | dispositivo removido ou escrita falhou; dispara uma vez |
| `onRaw(fn)` | todo report recebido, sem tratamento |

Depois de um `onDisconnect`, a instância não volta: para continuar, feche e abra o controle de novo.

### Dispositivo

A versão de firmware vem do controle e, pelo dongle, também do dongle. No cabo, `dongle` vem vazio.

```ts
const { firmware, dongle } = await pad.readFirmwareVersion();
```

<GamesirTry demo="firmware" />

`switchProfile` troca o perfil de jogo ativo. A coluna de LEDs entre os analógicos acende um LED por número de perfil, então dá para ver a troca.

```ts
await pad.switchProfile(3);   // 1 a 4, ou "Shift"
```

<GamesirTry demo="switch-profile" />

`vibrate` liga os dois motores, cada um de 0 a 255, e desliga sozinho depois de `durationMs`. Com `durationMs = 0`, os motores ficam ligados até a próxima chamada.

```ts
await pad.vibrate(255, 0, 400);   // só o motor esquerdo, por 400 ms
```

<GamesirTry demo="vibrate" />

| Membro | Descrição |
|---|---|
| `readFirmwareVersion()` | `{ firmware: "3.4.6", dongle: "1.2.1" \| "", raw }` |
| `readCurrentProfile()` | perfil de jogo ativo: 1–4, ou 5 com a camada Shift |
| `switchProfile(1 \| 2 \| 3 \| 4 \| "Shift")` | ativa um perfil de jogo |
| `vibrate(left, right, durationMs = 1000)` | motores de 0 a 255; `durationMs = 0` não desliga sozinho |

### Perfis crus e pacotes

Por baixo dos métodos tipados, toda configuração é leitura e escrita de bytes num perfil. Estes métodos dão acesso direto a isso, para quem quer mexer num campo que a lib ainda não expõe. As gravações valem na hora; não existe "salvar".

| Membro | Descrição |
|---|---|
| `readProfile(n)` | imagem crua do perfil `n` (`Uint8Array`) |
| `writeProfile(n, data, offset = 0)` | grava bytes a partir de `offset` |
| `writeProfileImage(n, image)` | grava a imagem inteira enviando só o trecho que mudou |
| `send(packet)` | envia um pacote sem esperar resposta |
| `request(packet, { timeoutMs = 200, maxSends = 10, match })` | envia e espera resposta, reenviando; um pedido por vez |

## `Cyclone2`

`new Cyclone2(transport)`. Herda tudo de `GameSirController<Cyclone2State>` e acrescenta métodos que entendem os perfis do Cyclone 2.

### Luz

O Cyclone 2 guarda quatro animações de luz do usuário e toca uma de cada vez; a quinta do perfil é a que ele toca enquanto carrega. Cada animação tem de 1 a 8 quadros, e cada quadro dá uma cor a cada zona: `Home`, `LowerLeft` e `LowerRight` (as laterais) e `UpperRight` (a coluna entre os analógicos). A zona `UpperLeft` existe no perfil, mas não tem LED. Uma cor fixa é só uma animação de um quadro. As mudanças ficam gravadas no controle.

`setStaticColor` é o atalho para uma cor fixa. Com uma cor, pinta todas as zonas:

```ts
await pad.setStaticColor("#00aaff");
```

<GamesirTry demo="static-color" />

Com um objeto, pinta só as zonas que você passar. As outras ficam apagadas:

```ts
await pad.setStaticColor({ Home: "#ff0000" });
```

<GamesirTry demo="static-zones" />

`applyPreset` aplica um dos efeitos prontos do app: Flow, Rainbow, Pulse, Standoff, Alarm ou Off. O preset vai para o slot ativo, ou para o slot que você passar, e esse slot passa a tocar.

```ts
await pad.applyPreset("Rainbow");
```

<GamesirTry demo="preset" />

Para uma animação sua, monte os quadros com `animation` e grave com `setAnimation`. Sem `slot`, ela vai para o slot ativo. Por padrão, o slot gravado vira o ativo.

```ts
const blink = animation([{ Home: "#ff0000" }, { Home: "#0000ff" }], { speed: 15 });
await pad.setAnimation(blink, { slot: 3 });
```

<GamesirTry demo="animation" />

`setActiveAnimation` troca o slot que está tocando, como M + analógico esquerdo faz no controle.

```ts
await pad.setActiveAnimation(2);
```

<GamesirTry demo="active-animation" />

| Método | Descrição |
|---|---|
| `readLightProfile()` · `writeLightProfile(p)` · `updateLightProfile(fn)` | perfil de luz completo (`LightProfile`) |
| `setStaticColor(color \| { Home, LowerLeft, … }, { slot, brightness })` | uma cor em todas as zonas, ou uma por zona |
| `setAnimation(animation, { slot, activate = true })` | grava uma animação num slot (0–3) |
| `applyPreset(name, slot?)` | `"Flow"`, `"Rainbow"`, `"Pulse"`, `"Standoff"`, `"Alarm"`, `"Off"` |
| `setActiveAnimation(index)` | slot ativo, 0–3 |
| `setStandbyTime(min)` · `setRaiseToWake(bool)` · `setAudioReactive(bool)` | opções gerais da luz |
| `playLights()` · `showFrame(i)` | toca a animação ativa · pausa no frame `i` (0–7) |

### Perfil de jogo

Os perfis de jogo (1 a 4, mais a camada Shift no 5) guardam o comportamento dos controles: o que cada botão envia, as macros do L4 e do R4, os gatilhos, os analógicos e o giroscópio. Os métodos abaixo cobrem os ajustes mais comuns. Para o resto, `updateGameProfile` lê o perfil, deixa você mudar qualquer campo e grava de volta.

`remapButton` faz um botão enviar outra coisa: outro botão, uma tecla, ou até três teclas juntas.

```ts
await pad.remapButton(1, KeyCode.A, KeyCode.B);   // no perfil 1, A envia B
await pad.setReportRate(1, ReportRate.Hz1000);
```

Uma macro é uma sequência de passos no L4 ou no R4. Cada passo segura uma tecla por `holdMs`, e o `delayMs` conta do início desse passo ao início do próximo. Se o `delayMs` for menor que o `holdMs`, os passos se sobrepõem. Com `loop`, a sequência recomeça `loopMs` depois do fim do último passo.

```ts
await pad.setMacro(1, KeyCode.L4, [
  { key: KeyCode.A, holdMs: 50, delayMs: 100 },   // B começa 100 ms depois do A
  { key: KeyCode.B, holdMs: 50, delayMs: 0 },
], { loop: true, loopMs: 500 });
```

`setMacroRecording` usa a gravação do próprio controle: você aperta os botões no controle e ele grava a sequência com os tempos medidos.

| Método | Descrição |
|---|---|
| `readGameProfile(n)` · `writeGameProfile(n, profile)` | lê/grava um `GameProfile` (perfis 1–5) |
| `updateGameProfile(n, fn)` | lê, aplica `fn` e grava |
| `remapButton(n, button, ...keys)` | mapeia um botão (`KeyCode.Up` a `KeyCode.Capture`) para até 3 `KeyCode`s; sem teclas, desfaz |
| `setReportRate(n, rate)` | `ReportRate.Hz250`, `Hz500` ou `Hz1000` |
| `setMacro(n, KeyCode.L4 \| KeyCode.R4, steps, { holdToTrigger, loop, loopMs })` | grava uma macro; sem passos, desliga |
| `setMacroRecording(KeyCode.L4 \| KeyCode.R4, state)` | gravação pelo controle: `protocol.MacroRecordState.Start`, `Stop` ou `Cancel` |

## Estado: `Cyclone2State`

É o report de estado já decodificado. Ele chega pelo `onState` enquanto o heartbeat estiver ligado.

```ts
pad.onState((s) => console.log(s.batteryLevel, s.buttons.A, s.physical.buttons.A, s.imu.accel));
```

<GamesirLive />

Existem duas visões dos botões. `buttons`, os sticks e os gatilhos do topo já passaram pelo mapeamento do perfil ativo: com A remapeado para B, apertar A aparece como B. `physical` traz o que foi apertado de fato.

| Campo | Tipo | Conteúdo |
|---|---|---|
| `leftStick`, `rightStick` | `{ x, y }` | −1..1, Y positivo para baixo |
| `leftTrigger`, `rightTrigger` | `number` | 0–255 |
| `hat` | `"Up" \| "UpRight" \| … \| null` | D-pad |
| `buttons` | `Buttons` | A, B, X, Y, LB, RB, LT, RT, View, Menu, LS, RS, Home, Capture, L4, R4, M |
| `physical` | `Inputs` | sticks, gatilhos, D-pad e botões físicos, antes do mapeamento do perfil |
| `imu` | `{ counter, gyro, accel }` | `gyro` e `accel` são `{ x, y, z }` crus (8192 LSB/g; eixos em [protocolo.md](protocolo.md#imu)) |
| `batteryLevel` · `chargeState` | `number` | % · 1 = carregando |
| `lightConfigIndex` | `number` | animação de luz ativa |
| `leds` | `Record<LedZone, Rgb>` | cor exibida em cada LED |
| `macroRecording` · `macroRecordKey` | `boolean` · `KeyCode.L4 \| KeyCode.R4 \| null` | gravação de macro em curso |
| `raw` | `Uint8Array` | report cru |

## Tipos e funções do Cyclone 2

Funções sem I/O que montam, leem e convertem os perfis, e os tipos que descrevem cada campo. Servem para preparar uma configuração antes de gravar ou para ler um dump.

### Luz

| Exportação | Descrição |
|---|---|
| `animation(frames, { speed = 10, brightness = 100 })` | monta uma `Animation`; `frames`: 1–8 objetos `{ zona: cor }` |
| `frame(colors)` · `solidFrame(color)` | um frame por zona · a mesma cor em todas |
| `applyPreset(animation, name)` · `PRESETS` | aplica um preset do app a uma animação |
| `encodeLightProfile(p)` · `decodeLightProfile(bytes)` | codec dos 635 bytes |
| `LightProfile` | `activeAnimation`, `animations` (5), `audioReactiveMode`, `raiseWakeUp`, `standbyTime`, `userEffectIndex`, `profileLed`, `reserved` |
| `Animation` | `keyFrameCount`, `speed` (0–20), `brightness` (0–100), `frames` (8 × `Frame`), `effectCount` |
| `LedZone` | `"Home"`, `"LowerLeft"`, `"LowerRight"`, `"UpperLeft"`, `"UpperRight"` |

Cores (`ColorInput`): `"#rrggbb"`, `[r, g, b]` ou `{ r, g, b }`. `hsv(h, s, v)` converte de HSV.

### Perfil de jogo

| Exportação | Descrição |
|---|---|
| `encodeGameProfile(p)` · `decodeGameProfile(bytes)` | codec dos 680 bytes |
| `GameProfile` | `name`, `fun`, `buttons` (16), `L4`, `R4`, `LT`, `RT`, `leftStick`, `rightStick`, `gyroAim`, `gyroTilt` |
| `KeyMapping` | `turboEnabled`, `turboSpeed`, `mapEnabled`, `mapTo` (3 `KeyCode`s), `toggle` |
| `Macro` · `MacroStep` | `enabled`, `holdToTrigger`, `loop`, `loopMs`, `steps` · `key`, `holdMs`, `delayMs` |
| `Trigger` · `Stick` · `Motion` | gatilho (deadzone, hair trigger, curva) · analógico · giroscópio |
| `MAPPED_BUTTONS` | ordem dos 16 botões mapeáveis |
| `ReportRate`, `StickOutput`, `CurveType`, `MotionActivation`, `HairTriggerMode`, `MOTOR_LEVELS` | valores aceitos nos campos |
| `KeyCode` · `keyName(code)` | códigos de tecla e nome reverso |

### Constantes

| Exportação | Valor |
|---|---|
| `Cyclone2Pid` | `{ Wired: 0x101D, WiredAdc: 0x1053, Wireless: 0x102A, WirelessDongle: 0x100B }` |
| `DONGLE_IDLE_PID` | `0x0575`, dongle sem controle (não responde) |
| `GAME_PROFILE_SIZE` · `LIGHT_PROFILE_SIZE` | 680 · 635 |
| `cyclone2` | descritor do modelo (`ControllerModel<Cyclone2State>`) |

## Baixo nível

Para quem quer montar os pacotes à mão, ou dar suporte a outro controle da família.

| Exportação | Descrição |
|---|---|
| `protocol.*` | montagem e leitura de pacotes, sem I/O: `heartbeat`, `readProfile(n, size)`, `writeProfile`, `vibrate`, `setMacroRecord`, `parseResponse`, `parseFirmwareVersion`… |
| `Cmd`, `Profile`, `VENDOR_ID`, `CONFIG_USAGE_PAGE`, `*_REPORT_ID` | constantes do protocolo |
| `diffRange(a, b)` | primeiro e último byte diferentes entre duas imagens |
| `HidTransport` | interface do transporte: `write(report)`, `onReport(fn)`, `onDisconnect?(fn)`, `close()`. O byte 0 é sempre o report ID |
| `ControllerModel` · `MODELS` · `modelForPid(pid, models)` | descritor de modelo · modelos conhecidos · busca por PID |

Um modelo novo do mesmo protocolo precisa de um `ControllerModel` (PIDs, tamanhos dos perfis, `parseState`) e, para métodos tipados, de uma subclasse de `GameSirController` com os codecs dos perfis dele.
